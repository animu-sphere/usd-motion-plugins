# motionRecording

`motionRecording` is where a stream becomes a clip: timestamped intake of
already-decoded poses, the recorder that turns what was sampled back into a
`MotionClip`, the `motion-capture-trace` text format, and the replay that feeds
a recorded trace through the same intake
([MOTION_CONTRACT.md §9–§10](../../docs/design/MOTION_CONTRACT.md#9-motionstream-intake)).

It is a **plain static CMake library** above
[`motionSampling`](../motionSampling/README.md), with the same boundary: no USD
stage, `Sdf`, `Plug` or file-format dependency, only OpenUSD's `Gf` value types
— and no transport and no wall clock. See
[WORKSPACE.md §2](../../docs/architecture/WORKSPACE.md#2-dependency-directions)
for the edges, enforced by [`tests/check_boundaries.py`](tests/check_boundaries.py).

It arrived from `usd-vrm-plugins` on 2026-09-19 with its history, as the
capture half of that repository's `motionRuntime`, and was renamed on arrival
([DESIGN_POLICY.md §42.2](../../docs/design/DESIGN_POLICY.md#422-names-are-this-policys-applied-on-arrival)).

## What it provides

| Header | Contents |
| --- | --- |
| `motionRecording/LiveCaptureSource.h` | `LiveCaptureSource` — timestamped intake, confidence gating, missing-joint policy, root-motion intake, statistics |
| `motionRecording/CaptureTrace.h` | The `motion-capture-trace` text format: reader, writer, error reporting |
| `motionRecording/ReplaySender.h` | `ReplaySender` — pushes a recorded trace as a caller-driven clock advances |
| `motionRecording/MotionRecorder.h` | `MotionRecorder` — accumulates evaluated poses back into a `MotionClip`, with the status of every tick |

`LiveCaptureSource` is the imported shape of the contract's `MotionStream`:
push into a buffer, pull by sampling. Whether the published stream is that,
a pull interface or a push interface is MC-O5, decided by `motion-connectors`'
first consumer, so the imported name is kept until then.

## No transport, no wall clock

Live capture arrives through `LiveCaptureSource::Push` as an already-decoded
pose stamped in the capture system's own clock; protocol decode and coordinate
conversion belong to a connector, and the caller drives every tick. That is
what makes a recorded session replay identically on every run and every OS, and
it is enforced by the boundary check, which refuses socket and HTTP headers.

The recorded traces the suites replay live in
[`tests/corpus/`](tests/corpus/README.md) and are generated by
[`tools/generate_traces.py`](tools/generate_traces.py).

## Building

It builds as part of the repository root `CMakeLists.txt`. Standalone:

```sh
cmake -S libs/motionRecording -B build/motion-recording \
      -DCMAKE_PREFIX_PATH="<usd-install>;<motionCore-install>;<motionSampling-install>"
cmake --build build/motion-recording --config Release
ctest --test-dir build/motion-recording -C Release --output-on-failure
```

Consumers use the installed package contract:

```cmake
find_package(motionRecording CONFIG REQUIRED)
target_link_libraries(consumer PRIVATE motionRecording::motionRecording)
```
