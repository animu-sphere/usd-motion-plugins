# v0.5.4: motion-owned validation and typed USD reader results

Release date: 2026-10-07.

## Objective

Provide the installed owner APIs needed by runtime consumers to remove private
motion validation, skeleton conversion and source-rest rebuilding. Preserve
canonical gaze and explicitly selected scalar inputs through USD interchange,
and refuse unusable motion clocks before conditioning history or producing clips.

## What ships

All seven libraries, the `execMotion` bundle and three CLIs are rebuilt at 0.5.4
for the existing Windows x64, macOS arm64 and Linux x64 OpenUSD 26.08 targets.

- `motionCore/Validation.h` and `motionRetarget/Validation.h` provide read-only
  value/configuration reports with owned code, subject and detail.
- `motionUsd::ReadMotionSkeleton` returns a validated descriptor, explicit
  generic or semantic-source interpretation, optional source rest and separate
  metre placement metadata. `ReadCanonicalMotionStage` retains compatible raw
  fields and returns descriptor/source rest together. `motionRetarget` is now a
  public dependency of `motionUsd`, including installed CMake discovery.
- Common clip-space gaze round trips through `motion:lookAtTarget`.
  `MotionStageReadOptions` projects owner-selected scalar/gaze attributes;
  its strict-reader overload keeps the same profile and owner diagnostics.
- `AuthorSkeletonAnimation` bakes evaluated target-local samples onto a
  composed skeleton, preserving references, target rest scales and stage
  metadata, with refusal/rollback behavior.
- USD and live-motion timeline checks reject nonfinite timestamps, rates,
  converted times and overflowing adjacent spans. Invalid input leaves outputs
  or conditioning history unchanged, as specified by each owner API.

The owning contracts are [MOTION §14](../design/MOTION_CONTRACT.md#14-generic-validation-ownership),
[MOTION §9.1.1](../design/MOTION_CONTRACT.md#911-existing-temporal-primitives),
and [USD §4.4–§7.3](../design/USD_MAPPING.md#44-gaze-points).

## Validation

Owner regression suites cover validation reports, generic/semantic skeleton
interpretation, descriptor/rest builder parity, referenced-stage resolution,
units and placement, authored rest, copy/stage lifetime, selected input presence
and timing, malformed input, target animation authoring and clock extremes.
Installed consumers check the public headers, linked symbols and transitive
retarget dependency. The tag release lane builds, tests, packages and publishes
the existing three OS targets before assembling the GitHub release.

## Consumer adoption

Use the generated `external-library-pins.json` or `.md` release asset to select
the 0.5.4 library/bundle/tool artifacts for the consumer's exact target. Rebuild
C++ consumers: `MotionStageRead` gains typed fields and its layout changes.
There is no new cross-toolchain C++ ABI guarantee or motion contract/vocabulary
version bump.

Runtime targets can consume `ReadMotionSkeleton(..., Generic)` directly,
retain explicit avatar/layout/joint identities and marshal baseline placement.
Source-clip consumers keep the strict read's clip and source rest together.
Permissive `ReadMotionStage` still supports raw-array fallbacks and leaves the
typed fields unset. Native format attribute discovery, host world placement,
runtime registration and ABI stabilization remain with their respective owners.
