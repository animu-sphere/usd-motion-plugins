# v0.5.0 — the first release: the shared motion foundation, installable

**Release status:** prepared on 2026-09-20.

## Objective

Make every identity in this repository **consumable from another repository**.
Until now the workspace built and tested but published nothing, so
`usd-vrm-plugins` held a second copy of every library that had already moved
here — which its own moving rules forbid
([its WORKSPACE.md §9.2](https://github.com/animu-sphere/usd-vrm-plugins/blob/main/docs/architecture/WORKSPACE.md#92-moving-rules),
rule 1). This release is what lets that copy be deleted.

## Why one tag carries five releases' scope

[The roadmap's scope table](../roadmap/README.md#status-at-a-glance) numbered
five releases, v0.1.0 to v0.5.0, one per group of identities arriving from
`usd-vrm-plugins`. Every one of those groups arrived between 2026-09-19 and
2026-09-20 — the imports ran faster than releases could be cut, because each
import shortens the time the sending repository holds a second copy.

Cutting five tags in one day would publish four artifact sets nothing would
ever pull. The scope table stays as the record of which row carried what, and
the version is the last row's: **0.5.0**. A consumer therefore pins
`>=0.5,<0.6`.

## What ships

### Seven libraries, as digest-pinned artifacts

| Library | What it is |
| --- | --- |
| `motionCore` | `HumanJoint`, `MotionPose`, `RootMotion`, `MotionChannelSet`, `SourceMetadata`, `MotionClip` — the value types every other library builds on, and no OpenUSD dependency |
| `motionSampling` | `SampleClip`, interpolation, `PoseFilter::Step`, the N-way `BlendPoses` |
| `motionRecording` | stream intake, `MotionRecorder`, the `motion-capture-trace` format (version 4) |
| `motionRetarget` | `SkeletonDescriptor`, `RetargetMap`, rest-pose correction, root-motion policy |
| `motionUsd` | both halves of the stage bridge: authoring and reading `/Animation/{Skeleton,Body,Channels}` |
| `motionSource` | recorded sources behind declarative producer profiles |
| `motionBvh` | the BVH reader |

Each is published to one OCI repository,
`ghcr.io/animu-sphere/usd-motion-plugins`, tagged
`<library>-0.5.0-<target>`, for the three targets the ecosystem pins. The
release's **pin table** (`external-library-pins.md` / `.json`, and inside the
notes) is generated from what was actually pushed, so a consumer pastes it
rather than transcribing digests.

### Three CLIs and one bundle, attached but not published

`motion_convert`, `motion_bvh_inspect` and `motion_record`, and the optional
`execMotion` OpenExec bundle, ship as release assets. They are not pushed to
the registry because nothing pins them by digest yet; `usd-avatar-runtime`
needing `execMotion` is what would change that.

`execMotion` is the only member that requires OpenExec. Every library and tool
builds against a runtime without the exec libraries.

## What it is verified by

- The whole CTest suite on Windows, macOS arm64 and Linux, against the three
  digest-pinned OpenUSD 26.08 runtimes the ecosystem shares.
- Each library built, tested and packaged **as its own artifact**, from its own
  isolated install prefix, on each of those three platforms.
- The `execMotion` pyramid: L5 on Linux, which the PR lane proves on every
  change; L4 on Windows and macOS, which have never run it (the flatten step is
  where a hosted Windows golden picks up semantic CR).
- The installed-consumer lane, which configures a consumer outside the
  repository against the installed prefix.

## What this release does not settle

- **The consuming half.** `usd-vrm-plugins` switches its nine members to these
  packages and deletes its copies in its own change; `usd-mmd-plugins` and
  `motion-connectors` follow. Until those land, the parity evidence its MIG-0
  named has not been reproduced across the move.
- **Publishing credentials.** The first push is also the first time
  `GITHUB_TOKEN` creates this repository's GHCR package. If it is refused, a
  PAT with `write:packages` replaces it; the workflow says so rather than
  assuming.
- **Package visibility.** A new GHCR package is private, and making it public
  is a manual flip in the package's settings. Publishing everything to one
  repository makes that one flip rather than seven.
- The open questions the contracts carry are unchanged: they are listed in
  [the roadmap](../roadmap/README.md#open-decisions).
