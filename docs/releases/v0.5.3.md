# v0.5.3: carry a missing intermediate's rotation into its ancestor

Release date: 2026-10-04.

## Objective

Let a caller retain the rotation of an upper chest on a target that binds
chest and neck but has no upper chest, without changing existing bakes.
[Issue #35](https://github.com/animu-sphere/usd-motion-plugins/issues/35)
reports the loss from VRMA and mocopi clips on PMX targets; the same case
exists on any humanoid rig without that optional joint.

## What ships

Every library, the `execMotion` bundle and the three CLIs, rebuilt at 0.5.3.
`RetargetOptions::foldUnboundIntermediateRotations` is a new boolean,
**false by default**. When enabled it composes qualifying missing source
intermediates into their nearest bound ancestor before rest correction,
removing each intermediate's local rest. The source states its hierarchy
through `SourceRestPose::parents`, or reads it with `BuildSourceRestPose`.
The bound descendants must be below the receiver on the target.

The ancestor carries the rotation for its whole subtree, so a missing upper
chest's rotation reaches both arms and the neck together. This preserves
world rotations for that compressed chain, not segment positions or separate
degrees of freedom in independent branches. An undriven ancestor can become
driven by a carried rotation; otherwise it retains its UsdSkel rest.
Unbound bones remain diagnostic subjects, with the receiver added to the
detail. Root motion, translations, rest scales and the input pose are
unchanged.

The binding contract and eligibility limits are
[RETARGETING_POLICY.md §4.2](../design/RETARGETING_POLICY.md#42-opt-in-folding-of-unbound-intermediate-rotations).
No format-specific rule or new OpenExec node is added: a caller holding a
`PoseRetargeter` passes the same options to the pose and clip paths.

## Validation

- Windows: the whole workspace's `ost build` and `ost test` under `ost`
  0.23.14 and OpenUSD 26.08; all 54 CTest tests pass, assertions enabled.
- Three added tests in `motionRetarget_unit` compare original source and
  target world rotations with non-identity source rests (upper chest 35°,
  neck 47°), a target-only collar and target reference rest; compose multiple
  missing joints in an order different from vocabulary order; cover an
  undriven ancestor and an absent intermediate; and retain default behaviour
  for missing roots/leaves, missing hierarchy, cycles, invalid parents,
  incompatible target branches, colliding or foreign maps, and an unordered
  target. Clip and single-pose results agree and diagnostics deduplicate.
- The existing hierarchy-mismatch test keeps the default loss explicit.
  The new parity fixture uses synthetic values and distributes no model or
  captured clip.

## Consumer adoption

Move the installed package pins to 0.5.3 and enable the option on the caller's
`RetargetOptions`. Keep the source parents and source rest from the clip's
semantic skeleton, and keep any target reference rest in `targetRest`.
Format repositories own the UI, CLI or scene statement that enables it.
The publication path remains the three existing OS targets, the existing
OCI repository and the generated per-member consumer pin table.
